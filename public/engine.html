How to load an engine

The engine is the part that fetches and rewrites web pages. It lives in the folder engines/active/. The interface, accounts and safety rules are separate, so you can swap the engine for a newer one (for example RME 2.3) without touching anything else. The folder itself stays; only what is inside it changes.

Replace the engine (recommended way)

Run these in a terminal, in the Rammerhead Stream folder. The installer backs up the old engine for you.

  1. Stop the app. Press Ctrl+C in the terminal where it is running.
  2. Install the new engine: point it at the folder (or .tgz / .zip-extracted folder) that contains the new engine. 
    npm run engine -- install /path/to/new-engine

    This reads and checks the engine's manifest.json and moves the old engine to engines/_backups/. It does not run the new engine.

  3. Set it up: installs the engine's own dependencies and builds it. 
    npm run engine:setup

    Only this step and the next one run the new engine's code, so look it over first if you do not fully trust where it came from.

  4. Check it works: loads the engine and tests it. 
    npm run engine -- validate

    You should see VALIDATION PASSED. If not, read the message, or roll back (below).

  5. Start the app. 
    npm start

    Reload this page: the engine name and version above should be the new one.

Something went wrong? Roll back

npm run engine -- rollback

This puts the previous engine back (and keeps the one you just tried as a backup). npm run engine -- backups lists every backup, and npm run engine -- rollback <name> restores a specific one.

The manual way (same result)

  1. Stop the app.
  2. Open the folder engines/active/. Copy its contents somewhere safe if you may want the old engine back.
  3. Delete everything inside it, but keep the active folder itself.
  4. Copy the new engine's files into engines/active/ so that manifest.json sits directly inside it (not in a sub-folder).
  5. Run npm run engine:setup, then npm run engine -- validate, then npm start.

What makes an engine valid

An engine is a folder with a manifest.json and an entry file:

engines/active/
  manifest.json      describes the engine (below)
  index.js           exports create(host) and returns the engine
  package.json       its own dependencies (optional)
{
  "contract": 1,
  "id": "my-engine",
  "name": "My Engine",
  "version": "2.3.0",
  "entry": "index.js",
  "node": ">=20",
  "capabilities": { "websocket": true, "scriptEngines": ["js"] }
}

Transports. An engine lists the connection methods it can use in capabilities.transports (for example ["http", "libcurl", "epoxy"]). Settings only offers what the installed engine lists, and a transport the engine does not list is refused. Make sure your engine really supports a transport before listing it: a transport only works if the engine is built and paired for it. See docs/ENGINES.md.

contract is the engine-interface version the engine was written for. This app supports contract 1. The full list of what create(host) must return is in docs/ENGINES.md in the project folder.

Transports (plug-ins)

A transport is the method used to carry the engine's requests to the web. The built-in HTTP method is always there. libcurl and Epoxy come with the project as plug-ins in transports/<name>/. You can remove them, replace them, or add others the same way you replace an engine.

Compatibility. A transport can only be used if the installed engine supports it. Installing a transport that your engine does not support does nothing: Settings will list it as unusable and refuse to select it. Before you add a transport, make sure your engine is built for it.

  1. See what is installed: 
    npm run transport -- list
  2. Add another transport, or put back libcurl or Epoxy after removing them (this downloads the official package from npm; add --accept-license after reading its license): 
    npm run transport -- add libcurl --accept-license
    npm run transport -- add epoxy --accept-license

    Or install a plug-in you already have: npm run transport -- install /path/to/transport.

  3. Remove one (it is backed up first, so it can be brought back with npm run transport -- rollback): 
    npm run transport -- remove libcurl
  4. Restart the server, then pick the transport in Settings → Connection, where you can also name a fallback and test it.

Licenses. libcurl and Epoxy are published under the AGPL-3.0, the same license as this project, and ship with their license text and a notice naming the exact package. Anything else you add has its own license; the command shows it before it installs anything.

Security. Transports of this kind usually connect through a Wisp server, which relays connections for whoever can reach it. Make sure any such server requires sign-in and refuses private networks, in the same way this site does.

If the engine is not working

The app keeps running and tells you why. The status above (and the banner inside the app) will be one of:

StatusWhat it meansWhat to do
readyEngine loaded and healthy.Nothing.
missingengines/active/ is empty or has no manifest.json.Install an engine (steps above). Make sure manifest.json is directly inside the folder.
invalid-manifestmanifest.json is broken, or the entry file does not export create().Run npm run engine -- status to see each problem.
incompatibleWritten for a different contract version, needs a newer Node.js, or does not provide everything the contract requires.Get an engine built for contract 1, or update Rammerhead Stream.
failedThe engine threw an error while loading (often missing dependencies).Run npm run engine:setup, then npm run engine -- validate and read the message.

The app never silently switches to an incompatible engine. While the engine is unavailable you can still sign in; browsing is switched off until it is fixed.
